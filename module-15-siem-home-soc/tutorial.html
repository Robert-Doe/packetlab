Module 15 — Tutorial

Goal: take Module 14's one-shot detection scripts and build a real, continuously-running pipeline around them — logs shipped into Elasticsearch, visualized in Kibana and Grafana, instead of reading terminal output once and moving on.

What was tested, and what wasn't: log_shipper.py/.js were fully tested — they produce genuinely valid Elasticsearch Bulk API NDJSON and Logstash-ready JSON lines, confirmed by self-validation during this module's build. docker-compose.yml's syntax was validated with docker compose config (confirmed correct, no daemon required) but the stack itself was NOT brought up during this module's build — bringing up a 4-container ELK+Grafana stack is a genuine resource commitment worth making deliberately, on your own schedule, not as a side effect of building course material. Bring it up yourself following Step 1 below.

Step 1 — bring up the stack

cd module-15-siem-home-soc
docker compose up -d
Expected: 4 containers start (elasticsearch, logstash, kibana, grafana). Give Elasticsearch 30-60 seconds to become healthy before continuing — docker compose ps should show it as healthy.

Step 2 — generate real findings and ship them

cd ../module-14-network-security-monitoring
python generate_conn_log.py
mkdir -p ../module-15-siem-home-soc/data
cp conn.log ../module-15-siem-home-soc/data/

cd ../module-15-siem-home-soc
python log_shipper.py
Expected: alerts.jsonl and bulk.ndjson are created. Copy alerts.jsonl into ./data/ too — Logstash's file input is watching that directory (per logstash.conf).
cp alerts.jsonl data/
docker compose restart logstash

Step 3 — see it in Kibana

Open http://127.0.0.1:5601. Go to Stack Management → Data Views, create one matching module15-conn-* and another for module15-alerts-*. Then Discover → pick the alerts data view.

Expected: the 3 sample alerts from log_shipper.py appear as documents, with their type, src, dst fields intact and a real @timestamp Logstash's date filter assigned.

Step 4 — import the Grafana dashboard

Open http://127.0.0.1:3000 (login: admin / changeme_before_real_use — CHANGE THIS if you keep the stack running beyond this lab). Add an Elasticsearch data source pointing at http://elasticsearch:9200 (or host.docker.internal depending on your Docker network setup), then Dashboards → Import → paste grafana_dashboard.json's contents.

Expected: 5 panels render — alerts by type (pie chart), alerts over time, port scan sources table, beaconing candidates table, and a connection-volume stat panel.

Step 5 — real Zeek/Suricata data, not just samples

If you completed Module 14's optional Step 5 (real Zeek/Suricata in your Module 09 lab), point logstash.conf's file input at your REAL conn.log instead of the synthetic one, and watch actual lab traffic flow through the same pipeline.

Exercises before Module 16

  1. Wire Module 14's actual detectors into this pipeline. Modify log_shipper.py to import and call conn_log_analyzer.detect_port_scans/ detect_beaconing directly (rather than using SAMPLE_ALERTS), so real detection findings ship automatically instead of being hand-typed.
  2. Add a Kibana alert. Under Stack Management → Rules, create a rule that fires when a new document appears in module15-alerts-* — this is the beginning of genuine "SIEM" behavior: not just visualizing past events, but reacting to new ones.
  3. Tear it down and bring it back up cleanly. docker compose down -v, then up -d again, and re-run Steps 2-4 from scratch. Being comfortable destroying and rebuilding your own SOC pipeline is a real operational skill, not just a formality.
Before Module 16: you should have a running ELK+Grafana stack you brought up yourself, with at least one dashboard showing real data you shipped into it.
