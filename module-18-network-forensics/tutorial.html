Module 18 — Tutorial

Goal: build a genuinely valid .pcap file from scratch, then reconstruct a full incident narrative from it — reconnaissance, exploit, exfiltration — purely by parsing the raw capture, the way a real incident responder works from evidence after the fact.

Step 1 — build a real incident capture

cd module-18-network-forensics
python pcap_writer.py
Expected: incident.pcap is created with 28 packets. Confirmed during this module's build with the independent file command-line utility (no relation to this course's code): file incident.pcap reports "pcap capture file, microseconds ts (big-endian) - version 2.4 (Ethernet, capture length 65535)" — genuine, external validation that this is a real, standards-conformant capture file, not a course-specific format.

Step 2 — open it in real Wireshark

Open incident.pcap directly in Wireshark.

Expected: Wireshark displays all 28 packets normally — source/dest IPs, TCP flags, and payload content exactly as this module built them. Use Follow → TCP Stream on the FTP exchange (packets around the 5-second mark) to see the USER smiley:) trigger string and the vsftpd banner reply in context, exactly like Module 14's Wireshark checklist taught.

Step 3 — parse it back with your own code

python pcap_reader.py incident.pcap
Expected: every packet's timestamp, addresses, ports, flags, and payload preview printed — confirmed during this module's build to exactly match what was written, byte for byte (the reconnaissance SYNs, the exploit payload, all 20 exfiltration packets).

Step 4 — reconstruct the full incident timeline

python incident_timeline.py incident.pcap
Expected: exactly 3 lines: a RECONNAISSANCE finding (6 ports scanned within 1 second), an EXPLOIT ATTEMPT finding (matching Module 16's real CVE-2011-2523 vsftpd trigger string), and an EXFILTRATION finding (20 packets, ~28KB, to a third-party host) — in correct chronological order, with real elapsed-time offsets. This is the entire job of Module 14's detection logic (port-scan and large-transfer patterns) applied retrospectively to a static capture instead of live traffic.

Step 5 — cross-language and Node

node pcap_writer.js
node pcap_reader.js incident_node.pcap
node incident_timeline.js incident_node.pcap
Expected: byte-identical output to the Python variants at every stage — confirmed during this module's build, including the generated .pcap files themselves being byte-for-byte identical once both languages used the same timestamp-rounding approach (a real cross-language porting detail worth noticing).

  2. Reconstruct a real capture from an earlier module. Take any Wireshark .pcap you saved from Modules 02, 07, or 08, and run pcap_reader.py against it directly. Confirm your hand-rolled parser correctly reads a file it never saw during development — real evidence your parsing logic is generically correct, not just fitted to this module's own synthetic data.
  3. Write an incident report. Using incident_timeline.py's output as your evidence, write a 2-3 paragraph incident report in plain English: what happened, in what order, and what specific evidence (packet numbers, timestamps, payload contents) supports each claim. This is the actual deliverable a real incident responder produces — the technical timeline is the input, not the output.
