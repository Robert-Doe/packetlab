Module 03 — Exam Practice

Answer out loud before revealing each answer.
Q1. Why does clearing your ARP cache require administrator/root privileges, when reading it (arp -a) does not?
A: The ARP cache is shared kernel state consulted by every process on the machine when sending traffic on the local network. Reading it is harmless information disclosure at worst. Modifying or clearing it could let an unprivileged process disrupt or redirect other processes' traffic (by removing legitimate entries or, worse, if insertion were unprivileged too, injecting fake ones) -- a real security boundary, not an arbitrary restriction.
Q2. Why does a switch's forwarding algorithm never need to inspect an IP header, even when forwarding frames that contain IP packets?
A: A switch operates purely at Layer 2 -- every forwarding decision (learn source MAC, flood or forward based on destination MAC and VLAN) uses only the Ethernet header's own fields. It treats whatever is encapsulated inside the frame (an IP packet, an ARP message, anything else) as opaque payload it never inspects, consistent with the encapsulation principle from Module 02.
Q3. Why is an ARP REQUEST always sent to the broadcast MAC address, while the REPLY is always unicast?
A: The requester, by definition, doesn't yet know the target's MAC address -- that's the entire question being asked -- so it has no specific MAC to address the request to, leaving broadcast as the only option that can reach the intended target without knowing its address in advance. The replier, by contrast, learned the requester's MAC directly from the request's own source MAC field, so it can (and does, for efficiency) unicast the reply straight back rather than broadcasting an answer only one host actually needs.
Q4. What are the exact contents of an 802.1Q tag, and why does the VLAN ID field cap out at 4096 possible values?
A: A 2-byte Tag Protocol Identifier (always 0x8100), followed by a 2-byte Tag Control Information field whose lowest 12 bits hold the VLAN ID. 12 bits can represent exactly 2^12 = 4096 distinct values (0-4095, with 0 and 4095 reserved) -- a hard architectural limit of the 802.1Q standard itself, which is why technologies needing more isolated segments than that (VXLAN, using a 24-bit identifier for over 16 million segments) were developed as a layered workaround.
Q5. Explain mechanically what a MAC flooding attack does to a switch, and why "failing open" is a dangerous default behavior.
A: The attacker sends frames from a very large number of distinct (often randomly generated) source MAC addresses, exhausting the switch's finite CAM table capacity. Once full, some switches "fail open" -- reverting to flooding every frame to every port, since they can no longer learn new mappings but must still forward traffic somehow. This is dangerous because it temporarily eliminates the traffic isolation a switch normally provides between ports -- an attacker on any port can now observe traffic addressed to other hosts on the same segment, functionally turning the switch into an old-style hub.
Q6. Why does switch_sim.py never touch your machine's real ARP cache, and what design principle does that reflect?
A: It maintains its own separate, in-memory CAM/ARP tables entirely within the simulation, rather than reading or writing any real OS-level networking state -- avoiding both the elevated privileges real ARP cache manipulation would require AND any risk of accidentally disrupting the student's real network configuration. This reflects the general design principle (seen throughout this course) of using real, correct algorithms while scoping any actual system-level side effects to the absolute minimum necessary for the lesson.
Q7. Synthesis: connect VLAN isolation (this module) to the "asymmetric trust" pattern from Module 09's home lab plan. What's the actual mechanical difference between VLAN isolation and firewall-rule isolation?
A: VLAN isolation (this module) works at Layer 2 -- different VLANs are simply never flooded to each other's ports at all; there's no packet-level decision being made, the switch structurally never sends VLAN 20's broadcast traffic to a VLAN 10 port in the first place. Firewall-rule isolation (Module 09/10) works at Layer 3/4 -- both VLANs might be ROUTED to each other by a router/firewall sitting between them, and the firewall then makes an explicit ALLOW/BLOCK decision per packet based on rules. VLANs prevent Layer 2 flooding from crossing a boundary at all; firewalls make deliberate, rule-based decisions about Layer 3 traffic that a router has already decided to forward between segments -- two different enforcement points working together, not the same mechanism applied twice.
