Module 19 — The Capstone

There's no new mechanism to learn here. Every tool, every concept, every technique you need for this module already exists in Modules 01-18. This module is about combining them into one coherent project — design, build, monitor, attack, defend, document.

Step 1 — read the brief and rubric completely

Read capstone_brief.md and capstone_rubric.html before building anything. Know what "done" looks like before you start.

Step 2 — verify the checker works, on the provided samples, before trusting it on your own project

cd module-19-capstone
python capstone_checker.py sample_manifest_complete.json
Expected: 100% completeness, no gaps.
python capstone_checker.py sample_manifest_incomplete.json
Expected: 0% completeness, 5 specific gaps — a missing firewall rule for a declared VLAN isolation rule, SIEM inactive, only 1 detector type, an unremediated vulnerability finding, and a too-short incident report. Confirmed identical between Python and Node during this module's build.

Step 3 — build your actual capstone

Follow capstone_brief.md's 5 requirements, using red_team_blue_team_playbook.md for the attack/defend cycle. This is genuinely the longest step, likely spanning days, not the one-sitting pace of earlier modules.

Step 4 — write your own manifest and check it

Copy sample_manifest_complete.json's structure, fill in YOUR real project's details, and run:

python capstone_checker.py your_manifest.json
Expected: work toward 100%, honestly — if the checker finds a gap, that's real information about your project, not a false alarm to explain away.

Step 5 — write the report and present it to yourself

Use final_report_template.md. Then, out loud, to yourself or someone else, explain your entire build without notes — the network design, the monitoring, the vulnerability you found and fixed, the incident you reconstructed. If you can do this fluently, you've actually learned the material this course spent 19 modules building toward.

You've finished the course. Every module from 01 through 19 was built and tested for real where testing was possible, and honestly scoped to guided exercises where real hardware, cloud accounts, or heavy infrastructure made full automation inappropriate. The vocabulary, mechanisms, and hands-on instincts you've built — from a subnet mask being an AND operation, to a TCP state machine, to a real X.509 certificate chain, to reconstructing an incident from a raw capture — are the actual foundation a PhD-level security researcher needs before specializing further. Good luck with what comes next.
