Module 12 — Deep Theory: WPA2 Cryptography, WPA3, and Commands From Zero

1. Command-by-Command: Monitor Mode Capture

sudo airmon-ng start wlan0

What it does: puts your wireless adapter into "monitor mode" — a special operating mode where the adapter captures EVERY 802.11 frame it can physically receive, regardless of destination MAC address or whether you're even associated with any network, and WITHOUT the normal 802.11-to-Ethernet translation your OS's networking stack usually performs automatically. Ordinary "managed mode" (what your Wi-Fi adapter uses for normal internet access) only surfaces frames addressed to you, already stripped of most 802.11-specific header detail — monitor mode is the wireless equivalent of the raw capture privilege Module 02 discussed for wired Ethernet, requiring the same kind of elevated access and specific hardware/driver support.

sudo airodump-ng wlan0mon

What it does: reads raw 802.11 frames from the monitor-mode interface airmon-ng just created (note the mon suffix — a new virtual interface distinct from the original wlan0) and displays a live summary: every visible SSID/BSSID, signal strength, channel, and encryption type — built directly from parsing beacon frames exactly like wifi_frame_builder.py constructs, just captured from the air instead of built in code.

2. PBKDF2, Formally

PBKDF2 (Password-Based Key Derivation Function 2, RFC 2898) takes a human-memorable password (low entropy — predictable, guessable, typically far fewer than 256 bits of true randomness) and stretches it into a fixed-length cryptographic key, DELIBERATELY slowly, via repeated HMAC iterations:

PMK = PBKDF2(HMAC-SHA1, passphrase, salt=SSID, iterations=4096, keylen=256 bits)

The SSID serves as the "salt" — meaning two networks with the IDENTICAL passphrase but DIFFERENT SSIDs produce completely different PMKs. This is a deliberate defense against precomputed lookup tables (rainbow tables): without a salt, an attacker could compute PMKs for common passwords ONCE and reuse that table against every network using those passwords. Salting with the SSID forces a SEPARATE precomputation per SSID, dramatically raising the cost of building a reusable attack table.

Comprehensive exam framing: "Why does WPA2-PSK use only 4096 PBKDF2 iterations, when modern password-hashing guidance (for things like web application login credentials) often recommends hundreds of thousands of iterations or memory-hard alternatives like Argon2?" 4096 is fixed by the IEEE 802.11i specification itself and cannot be increased without breaking interoperability with every existing device implementing the standard — WPA2 predates modern password-hashing best practices, and the number was chosen as a reasonable-for-its-time balance between security and computation cost on period-appropriate hardware (including low-power embedded devices that need to derive this key quickly). This fixed, comparatively low iteration count is precisely why WPA2 handshakes captured from weak, short, or dictionary-word passphrases remain crackable via offline brute-force in practical timeframes today — the exam-relevant takeaway is that the STRENGTH of the passphrase itself matters far more for WPA2 than it would for a system using a modern, much higher iteration count.

3. WPA3 and SAE: What Changed, and Why

WPA3 replaces WPA2-PSK's 4-way handshake with SAE (Simultaneous Authentication of Equals, based on the "Dragonfly" key exchange), which provides TWO properties WPA2-PSK structurally lacks:

PropertyWPA2-PSKWPA3-SAE
Offline dictionary attack resistanceVulnerable — a captured handshake can be brute-forced offline against passphrase guesses, entirely on the attacker's own hardware, with no interaction with the real AP requiredResistant by design — SAE requires an ACTIVE, per-guess interaction with the real AP for each password guess, making offline brute-forcing structurally infeasible (an attacker must interact with the real network once per guess, which is detectable and rate-limitable)
Forward secrecyNo — if the PSK (passphrase) is later compromised, ALL previously captured traffic for that network can be decrypted retroactivelyYes — each session's keys are derived such that compromising the passphrase later does not let an attacker decrypt previously captured sessions
Brain power: why does "requires interaction with the real AP per guess" meaningfully change an attacker's economics, compared to WPA2's offline-crackable handshake? Offline attacks scale with the attacker's OWN available compute (GPUs, cloud compute rented at will, completely undetectable by the victim network). An attack requiring per-guess interaction with the real AP is bounded by the AP's own response rate, is directly observable/detectable by the network owner (unusual repeated authentication attempts), and can be rate-limited or locked out by the AP itself — fundamentally different attacker economics, even though both ultimately protect the same kind of secret (a passphrase).

4. Enterprise Wi-Fi: 802.1X/EAP, Briefly

Everything this module built assumes WPA2-PERSONAL (a single shared passphrase for the whole network — what a home network uses). WPA2/3-ENTERPRISE instead uses 802.1X port-based network access control combined with EAP (Extensible Authentication Protocol) — each user authenticates with THEIR OWN individual credentials (often via a RADIUS server checking against a corporate directory) rather than everyone sharing one passphrase. This means individual users can be revoked without changing a network-wide shared secret, and it produces individual accountability (which specific user's credentials were used) that a shared PSK fundamentally cannot provide — the actual reason large organizations use Enterprise mode despite its added infrastructure complexity (a RADIUS server is a real, separate piece of infrastructure this course doesn't build).
