Module 12 — Exam Practice

Answer out loud before revealing each answer.
Q1. What specifically does "monitor mode" enable that ordinary "managed mode" Wi-Fi operation does not?
A: Monitor mode captures every 802.11 frame the adapter can physically receive, regardless of destination MAC or whether the adapter is associated with any network, without the normal 802.11-to-Ethernet translation and filtering the OS networking stack performs in managed mode. Managed mode only surfaces frames addressed to you, already stripped of most raw 802.11 header detail -- monitor mode exposes the raw wireless frames directly, the wireless equivalent of raw packet capture privilege on wired Ethernet.
Q2. Why does WPA2-PSK use the SSID as PBKDF2's salt, and what specific attack does this defend against?
A: Using the SSID as salt means two networks with the IDENTICAL passphrase but DIFFERENT SSIDs produce completely different PMKs. This defends against precomputed lookup/rainbow tables -- without a salt, an attacker could compute PMKs for common passwords ONCE and reuse that table against any network using those passwords. Salting with the SSID forces a separate, SSID-specific precomputation, dramatically raising the cost of building a reusable attack table across multiple networks.
Q3. Why is WPA2's fixed 4096 PBKDF2 iteration count considered weak by modern password-hashing standards, and why can't it simply be increased?
A: Modern password-hashing guidance often recommends hundreds of thousands of iterations or memory-hard alternatives (Argon2) specifically to slow down offline brute-force attacks. WPA2's 4096 is fixed by the IEEE 802.11i specification itself -- increasing it would break interoperability with every existing device implementing the standard as written. This fixed, comparatively low iteration count is a real reason WPA2 handshakes from weak or short passphrases remain crackable via offline brute-force in practical timeframes.
Q4. Explain precisely why WPA3's SAE resists offline dictionary attacks in a way WPA2-PSK's 4-way handshake does not.
A: WPA2-PSK's handshake, once captured, can be brute-forced entirely offline -- an attacker tries password guesses purely on their own hardware with no further interaction with the real AP required. SAE requires an ACTIVE, per-guess interaction with the real AP for each password attempt, making offline brute-forcing structurally infeasible -- the attacker must interact with the real network once per guess, which is detectable, rate-limitable, and bounded by the AP's own response behavior rather than the attacker's own compute resources.
Q5. Define "forward secrecy" precisely, and explain why WPA2-PSK lacks it while WPA3-SAE provides it.
A: Forward secrecy means that even if a long-term secret (here, the passphrase/PMK) is compromised LATER, previously captured encrypted traffic from PAST sessions cannot be retroactively decrypted using that compromised secret. WPA2-PSK lacks this: since session keys (PTKs) are deterministically derived from the PMK plus exchanged nonces, anyone who captured a session's handshake AND later learns the passphrase can retroactively compute that session's PTK and decrypt it. WPA3-SAE's key derivation is designed so this retroactive computation isn't possible even with the passphrase later compromised, protecting past sessions.
Q6. What's the fundamental architectural difference between WPA2/3-Personal and WPA2/3-Enterprise, and why would a large organization prefer Enterprise despite its added infrastructure complexity?
A: Personal mode uses a single shared passphrase for the entire network -- everyone derives the same PMK from the same secret. Enterprise mode uses 802.1X/EAP, where each user authenticates with their OWN individual credentials, typically verified against a RADIUS server checking a corporate directory. This lets an organization revoke one specific user's access without changing a network-wide shared secret (which would require reconfiguring every other device), and provides individual accountability (which specific user's credentials were used for a given access) that a single shared PSK fundamentally cannot provide -- both significant operational advantages at organizational scale, justifying the added RADIUS infrastructure.
Q7. Synthesis: connect WPA2-PSK's offline-crackability to Module 16's vulnerability assessment mindset. What would a professional wireless security assessment actually recommend, and why?
A: A professional assessment would recommend (1) a long, high-entropy passphrase (since the fixed 4096-iteration PBKDF2 cannot be strengthened, passphrase entropy is the only lever actually available to resist offline brute-force), and (2) migrating to WPA3 where hardware supports it, specifically because SAE's active-interaction requirement changes attacker economics fundamentally rather than merely raising the computational cost of the same offline attack. This mirrors Module 16's general vulnerability-assessment principle: understand the ACTUAL mechanism of a weakness (here, offline-crackability of a captured handshake) precisely enough to recommend a fix that addresses the real mechanism, not just a surface-level mitigation.
