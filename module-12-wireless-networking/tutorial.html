Module 12 — Tutorial

Goal: understand the actual cryptography behind your Wi-Fi password — computed for real, not simulated — and see exactly what a beacon frame contains before ever touching real wireless hardware.

Scope for this module: real wireless packet capture requires a Wi-Fi adapter in "monitor mode," which needs specific hardware support and elevated privileges, and isn't available in this course's build/test environment. Everything in this file that generates output was tested for real. The hands-on wireless capture in Step 3 is a guided exercise for your OWN access point only — never capture or attempt to crack a network you don't own or have explicit authorization to test. See ../SAFETY.md.

Step 1 — the actual math behind your Wi-Fi password

cd module-12-wireless-networking
python wpa2_psk_derivation.py
Expected: the script computes a PMK and compares it to f42c6fc52df0ebef9ebb4b90b38a5f902e83fe1b135a70e23aed762e9710a12e — a published test vector (SSID IEEE, passphrase password) cited across WPA2 security literature for years. Confirmed matching during this module's build, in both Python and Node. This is the exact PBKDF2-HMAC-SHA1 computation every real access point and every real device performs the moment you type a Wi-Fi password.

Step 2 — the 4-way handshake, computed for real

python wpa_handshake_sim.py
Expected: AP and STA each compute a PTK independently, using only their own nonce, the peer's nonce (exchanged in messages 1-2), and both MAC addresses — the PMK itself is never transmitted, and neither is the PTK. The script confirms both sides arrive at byte-identical PTKs. This was verified during this module's build — Python and Node also produce identical PTKs from identical fixed inputs, confirming the PRF implementation is correct in both languages.

Step 3 — a real beacon frame, built by hand

python wifi_frame_builder.py
Expected: a 54-byte frame with a correctly parsed Frame Control field (type=Management, subtype=Beacon) and your test SSID extracted from its tagged parameter — the exact structure every AP broadcasts roughly 10 times a second, unencrypted.

Step 4 (your own AP only) — capture it for real

If you have a Wi-Fi adapter capable of monitor mode (many external USB adapters support this; most laptop built-in cards don't) and Wireshark or aircrack-ng installed:

# Linux example -- exact commands vary by adapter/driver
sudo airmon-ng start wlan0
sudo airodump-ng wlan0mon
Expected (against YOUR OWN AP only): you'll see your own SSID's beacon frames listed, readable in plaintext — matching Step 3's structure exactly. If you capture a real 4-way handshake (by watching a device reconnect to your own AP), you can compare the EAPOL message structure to Step 2's simulated exchange.
Only ever capture or analyze traffic on networks you own or have explicit written authorization to test. Capturing a neighbor's or employer's wireless traffic without authorization is illegal in most jurisdictions, regardless of whether you attempt to crack anything.

Exercises before Module 13

  1. Compute your own real network's PMK. Use your actual home Wi-Fi's SSID and passphrase (change it back afterward if you're worried about typing it into a script, or just use a test value) and see the real 256-bit key your devices already compute today.
  2. Add a Probe Request frame. Extend wifi_frame_builder.py/.js to build subtype 4 (Probe Request) instead of subtype 8 (Beacon) — this is the frame your phone sends actively asking "is anyone here?", which is why hidden-SSID networks still leak their name (see the script's closing note).
  3. Time-attack the PBKDF2 iteration count. Modify derive_pmk to accept a custom iteration count, and time how long 4096 iterations takes vs. 100,000. This is directly why WPA2's PSK derivation being "only" 4096 iterations (fixed by the spec, unlike modern password hashing which often uses much higher counts) matters for offline dictionary attack speed — a topic Module 16 revisits from the attacker's side, in an authorized lab context only.
Before Module 13: you should be able to explain exactly what a PMK and PTK are, how they differ, and why neither is ever transmitted over the air even during the handshake that establishes them. Module 13 goes deeper into the cryptographic primitives underneath all of this — symmetric/asymmetric crypto, and a full TLS handshake dissection.
