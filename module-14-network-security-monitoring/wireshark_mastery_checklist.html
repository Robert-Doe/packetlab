Wireshark Mastery Checklist

You've used Wireshark since Module 02. This is the point where casual familiarity becomes fluency -- go through this against a real capture from ANY earlier module's traffic (Module 07's TCP/UDP echo demos work well).

Display filters beyond the basics

FilterWhat it finds
tcp.flags.syn==1 and tcp.flags.ack==0Only the FIRST packet of every TCP handshake -- great for counting distinct connection attempts, exactly what Module 14's port-scan detector does statistically.
tcp.analysis.retransmissionEvery segment Wireshark's own heuristics flagged as a retransmit -- direct visual evidence of Module 07's "TCP resends what wasn't acknowledged" behavior.
http.request.method=="POST"Only POST requests -- useful for spotting form submissions/logins in a capture.
tls.handshake.type==1Only TLS ClientHello messages -- find every negotiation attempt without wading through the encrypted data that follows.
ip.addr==192.168.1.30 and tcp.flags.syn==1Every SYN FROM or TO a specific host -- manually reconstructing what Module 14's port-scan detector does automatically.

Statistics menu -- underused, extremely powerful

ToolWhat it shows
Statistics → Protocol HierarchyA tree breakdown of every protocol present in the capture and what % of packets/bytes each represents -- your first move on any unfamiliar capture.
Statistics → ConversationsEvery unique src/dst pair with packet/byte counts and duration -- sort by "Bytes" to instantly find the biggest data transfers in a capture.
Statistics → EndpointsEvery unique host that appears, with total traffic -- useful for spotting an unexpected IP that shouldn't be talking on your network at all.
Right-click a packet → Follow → TCP StreamReassembles an entire conversation's payload in order, both directions color-coded -- this is how you actually READ an HTTP exchange or any text protocol end to end instead of packet by packet.

Exporting for other tools (including this module's own analyzer)

# Export a capture's connections as CSV for further analysis
tshark -r capture.pcapng -q -z conv,tcp

# Or, closer to Zeek's own conn.log format directly from tshark:
tshark -r capture.pcapng -T fields -e frame.time_epoch -e ip.src -e tcp.srcport \
  -e ip.dst -e tcp.dstport -e ip.proto

This is genuinely how you'd bridge a raw Wireshark/tshark capture into something shaped like conn_log_analyzer.py's expected input -- worth trying against one of your own earlier captures as an exercise.
