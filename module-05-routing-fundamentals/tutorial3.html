Module 05 — Exam Practice

Answer out loud before revealing each answer.
Q1. State the longest-prefix-match rule precisely, and explain why it's necessary for default routes and specific routes to coexist sensibly.
A: When multiple routing table entries match a destination, the router always selects the entry with the longest (most specific) prefix, regardless of insertion order or any other tiebreaker. This is necessary because a default route (0.0.0.0/0) matches every possible destination -- without a rule guaranteeing more specific routes win, a default route would make every other, more specific entry in the table pointless, since the default would always be an equally valid match.
Q2. Explain the core Bellman-Ford relaxation step, and identify exactly what assumption it makes that a dynamically-changing real network violates.
A: For each neighbor's advertised distance to a destination, compute (advertised distance + link cost to that neighbor); adopt it only if strictly better than the current known distance. The violated assumption: the textbook algorithm assumes a STATIC graph while it runs, with no concept of "my current route just got worse." A real network's links can fail after convergence, and strict relaxation alone will never revise AWAY from a route that has degraded, since a worse value is never accepted under the strict "only if better" rule.
Q3. What is the minimal, correct fix to Bellman-Ford relaxation for real dynamic routing, and why does it not violate the algorithm's core correctness?
A: A router must unconditionally accept updates from whichever neighbor is its CURRENT next-hop for a given destination, even when the update is worse -- because that neighbor IS the router's sole source of truth for that specific route, not merely one candidate among several to compare. This doesn't violate Bellman-Ford's correctness for OTHER (non-current-path) neighbors, where strict "only if better" relaxation still correctly applies -- the fix only changes behavior for the one neighbor a router is already trusting as its path's authority.
Q4. Why does split horizon fully solve a 2-router ping-pong but potentially fail to fully prevent count-to-infinity in a 3-router (triangle) topology?
A: Split horizon's rule (never advertise a route back to the neighbor you learned it from) directly breaks the specific 2-router cycle where stale information bounces directly between exactly two routers. With a third router providing a genuine alternate path, stale information can travel through that THIRD party instead -- Router A's stale belief can reach Router C, and C's own resulting (also now stale) advertisement can reach back toward B via a path that never directly violates split horizon's "don't tell the source" rule, because the information passed through an intermediate third router along the way.
Q5. What does "split horizon with poison reverse" add beyond plain split horizon, and why does this close more of the gap?
A: Rather than simply OMITTING a route when advertising back toward the neighbor it was learned from (plain split horizon), poison reverse explicitly advertises that route back as INFINITY (an explicit "this is unreachable via me" signal). This makes "this route is dead" propagate as positive, explicit information rather than requiring it to be inferred from an absence -- explicit bad news spreads faster and more reliably through a topology with multiple paths than an omission that could be misinterpreted or arrive too late relative to other, still-stale advertisements circulating through alternate paths.
Q6. Why does Dijkstra's algorithm (OSPF) not suffer from count-to-infinity, structurally -- not "because OSPF is better," but the actual mechanical reason?
A: Dijkstra requires and operates on the COMPLETE, freshly-flooded topology graph -- every router has an identical, direct copy of every link in the network, not a neighbor-summarized distance. There is no intermediate "trust your neighbor's claimed distance" step that could hold stale information, because nothing is ever summarized in the first place -- each router computes shortest paths directly from raw, complete connectivity facts, which is structurally incapable of producing the specific failure mode (trusting a neighbor's stale summarized belief) that causes count-to-infinity in distance-vector protocols.
Q7. Synthesis: why do real home routers almost never run RIP or OSPF, despite both being freely available protocols?
A: A home network typically has exactly one router and one path to the internet -- there is no actual topology complexity (no multiple routers needing to dynamically agree on best paths, no redundant links needing automatic failover) for a dynamic routing protocol to add value over. A single static default route (0.0.0.0/0 -> ISP gateway) captures the entire routing need correctly and with zero protocol overhead, convergence delay, or memory/CPU cost -- dynamic routing protocols exist to solve problems (multiple paths, automatic failover, large numbers of interconnected routers) that simply don't arise in a typical single-router home network topology.
