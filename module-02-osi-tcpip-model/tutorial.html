Module 02 — Tutorial

Goal: build a frame by hand (bytes you assemble yourself), then capture a real one crossing your own loopback interface, and confirm they agree. This is the module where "the OSI model" stops being a diagram you memorized and becomes bytes you can point at.

Step 1 — build a frame by hand, no network required

cd module-02-osi-tcpip-model
python layer_builder.py
Expected output: an annotated hex dump, four sections labeled Layer 2 (Ethernet, 14 bytes), Layer 3 (IPv4, 20 bytes), Layer 4 (TCP, 20 bytes), Layer 7 (HTTP, however long your request text is) — total 105 bytes. Read the closing note about Layers 5/6 (Session, Presentation) having no header at all in real TCP/IP traffic — that's the single most important "OSI vs TCP/IP" fact this module teaches.

Now run the JS version and diff the two outputs by eye:

node layer_builder.js
Same hex bytes, same 91-byte IP total length, same everything — two languages, one wire format.

Step 2 — install Wireshark (one-time, external tool)

This course doesn't ship Wireshark — it's a free, open-source capture tool you install yourself from wireshark.org. On Windows it installs Npcap alongside it (needed for raw capture access); on macOS/Linux your package manager has it (brew install --cask wireshark, apt install wireshark).

You may need to run Wireshark as Administrator/root, or add your user to the appropriate capture group (wireshark group on Linux) — this is normal; raw packet capture is a privileged operation on every OS, which is also why this course's own Python/Node code never attempts it directly (see DECISIONS.md).

Step 3 — capture a real request

  1. Open Wireshark, select your Loopback interface (Windows: "Adapter for loopback traffic capture"; macOS/Linux: lo0/lo).
  2. In the display filter bar, type tcp.port == 8080 and press Enter (filters the view; capture continues regardless).
  3. Click the shark-fin "start capture" button.
  4. In a terminal: 
    python http_target_server.py
  5. In a second terminal: 
    python traffic_generator.py
  6. Back in Wireshark, stop the capture (red square).
Expected: roughly 10 packets appear: 3 for the handshake (flags SYN, SYN, ACK, ACK), 1+ carrying your GET request, 1+ carrying the HTTP response, and 4 for teardown (FIN, ACK pairs in each direction) — matching exactly the 5 steps traffic_generator.py printed to your terminal. Click any packet and expand its layers in the middle pane — Wireshark labels them Frame → Ethernet II → Internet Protocol Version 4 → Transmission Control Protocol → Hypertext Transfer Protocol. That's the exact same 4-layer stack layer_builder.py built by hand in Step 1, this time captured for real.

Step 4 — find your marker

In Wireshark, use Edit → Find Packet, search for string LAYER-DEMO-PAYLOAD-92f1 in packet bytes. You should land on the response packet. Expand its Hypertext Transfer Protocol layer and find the marker in the response body — proof the exact bytes your Flask route returned are the exact bytes that crossed the interface.

Exercises before Module 03

  1. Change the HTTP method. Edit traffic_generator.py to send HEAD instead of GET. Re-capture. Confirm the response has no body but still has headers — map that difference to the layer it belongs to (Application layer semantics, not something Ethernet/IP/TCP care about at all).
  2. Break the handshake on purpose. Stop http_target_server.py, then run traffic_generator.py against the now-dead port. Capture what happens — you should see your machine's kernel reply with a TCP RST instead of a SYN-ACK, and your script should raise a ConnectionRefusedError. This is what "closed port" looks like at the packet level, foundational for Module 06's ping/traceroute work and Module 16's port scanning.
  3. Add a 5th layer to layer_builder.py. Try to justify adding a "Layer 6" header of your own invention between TCP and HTTP. You'll find there's nowhere for a real NIC/OS to put it — which is exactly the point: TCP/IP collapsed OSI's top 3 layers into one, because in practice nothing ever needed them separated.
Before Module 03: you should be able to point at any byte in a Wireshark capture and say which layer it belongs to, without Wireshark's own labels. Module 03 zooms into that first 14-byte Ethernet header specifically — MAC addresses, ARP, and how switches use that header alone to move frames around a LAN.
