Cisco IOS Command Reference

Every command used across this module's three topologies, grouped by what it does. Packet Tracer's simulated IOS accepts all of these exactly as a real router/switch would (this is genuinely one of Packet Tracer's core selling points — it's not a fake CLI, it's a real, if reduced, IOS command parser).

Interface configuration

interface GigabitEthernet0/0
 ip address 192.168.10.1 255.255.255.0
 no shutdown

no shutdown is the single most forgotten command in every first Packet Tracer lab ever built. Every interface starts administratively down — it stays down, and pings through it will fail with no useful error, until you explicitly bring it up.

Static routing

ip route <destination-network> <subnet-mask> <next-hop-ip>
ip route 198.51.100.0 255.255.255.0 10.0.12.2
ip route 0.0.0.0 0.0.0.0 203.0.113.1     ! default route

Note IOS wants the subnet mask in dotted-decimal (255.255.255.0), not CIDR (/24) — the opposite convention from subnet_calc.py's CLI in Module 04. Both represent identical information; only the notation differs.

Verification commands (run these constantly)

CommandWhat it shows
show ip routeThe full routing table — connected (C) and static (S) routes, exactly what topology_validator.py predicts.
show ip interface briefEvery interface's IP and up/down status in one table — the fastest way to spot a forgotten no shutdown.
show mac address-table(On a switch) the CAM table Module 03's switch_sim.py built in software — now populated by real (simulated) traffic.
show arpThe router's ARP cache — same concept as Module 01's dashboard and Module 03's ARP exchange, seen on IOS.
show running-configThe device's complete current configuration.

Testing connectivity

ping 198.51.100.20
traceroute 198.51.100.20

From a PC's Command Prompt (not the router CLI), the equivalent Windows-style commands are available: ping and tracert.

Saving your configuration

write memory
! or the older, equivalent form:
copy running-config startup-config

Packet Tracer does NOT auto-save router configs into the running simulation the way it auto-saves the topology layout itself. If you close and reopen the file without having run this, your typed IOS commands survive (they're part of the saved .pkt device state) — but on a real router, skipping this step means a power cycle wipes your configuration entirely. Build the habit now.
