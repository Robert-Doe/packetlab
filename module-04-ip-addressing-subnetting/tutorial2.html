Module 04 — Deep Theory: Subnetting and VLSM, Command by Command

1. Why CIDR Replaced "Classful" Addressing (History That Explains the Notation)

Before 1993, IPv4 addressing used rigid "classes": Class A (first octet 1-126, implying a /8 network — 16 million hosts), Class B (/16 — 65,536 hosts), Class C (/24 — 254 hosts), with the class determined entirely by an address's leading bits. This was catastrophically wasteful — an organization needing 300 addresses (too many for a Class C, "wasting" almost all of a Class B's 65,536) had no middle option. CIDR (Classless Inter-Domain Routing, RFC 1518/1519) replaced this with the /N notation this module uses throughout — ANY prefix length from 0 to 32 is valid, letting network size match actual need instead of snapping to one of three fixed sizes. This is WHY the notation is 192.168.1.0/26 rather than "Class C" — CIDR explicitly abolished the class concept.

2. Command-by-Command: What Step 2's Self-Test Actually Proves

python subnet_calc.py --self-test

What it does: generates 500 random IP/prefix combinations, computes network and broadcast addresses TWO independent ways — this module's own hand-rolled bitwise math, AND Python's official ipaddress standard library module — and confirms they agree every single time. Why this matters as proof, not just testing: the ipaddress module is Python's own officially maintained, widely-used, battle-tested implementation. Agreement across 500 random cases is strong evidence the hand-rolled bit math is CORRECT, not merely "looks right on the few examples I checked by hand."

node subnet_calc.js --self-test 50

What it does differently: Node has no bundled standard-library equivalent to Python's ipaddress module, so this test instead SHELLS OUT to subnet_calc.py (spawning it as a subprocess) and compares Node's own computed answer against Python's answer for the same random inputs. Why this is still valid proof: since Python's file was ALREADY validated against the `ipaddress` module, agreement between Node and Python transitively confirms Node against the same authoritative source, one hop removed — a chain of trust, not a weaker test.

3. The Bitwise Math, Fully Derived

Every value subnet_calc.py computes reduces to three operations on 32-bit integers, all from Module 00a's boolean algebra:

ValueFormulaWhy
Subnet mask0xFFFFFFFF << (32 - prefix)Left-shifting all-1s by (32-prefix) positions leaves exactly `prefix` 1-bits at the top, 0s filling in from the right
Network addressip AND maskAND is a "stencil" (Module 00a) — keeps IP's bits only where mask has 1s, zeroing the host portion
Wildcard maskNOT maskBit-for-bit inverse — 0s become 1s and vice versa, isolating exactly the host-portion bits
Broadcast addressnetwork OR wildcardOR is a "merge" — sets every host bit to 1 while leaving the already-correct network bits untouched
Usable hosts2^(32-prefix) - 2Total addresses in the block, minus the network address itself and the broadcast address (neither is assignable to a host)
Comprehensive exam framing: "Derive the broadcast address of 10.20.30.40/28 by hand, showing your work in binary." A strong answer computes the mask (/28 = 11111111.11111111.11111111.11110000 = 255.255.255.240), ANDs it with the IP to get the network address (10.20.30.32, since 40 = 00101000 and the mask's last octet keeps only the top 4 bits, giving 00100000 = 32), then ORs the network address with the wildcard mask (0.0.0.15) to flip the bottom 4 bits to all 1s, giving 10.20.30.47 — walking through the actual bit operations, not just stating memorized "block size" shortcuts.

4. VLSM's Allocation Algorithm, Formally

vlsm_allocate() implements a classic "first-fit decreasing" bin-packing strategy: sort requirements largest-first, then place each one at the SMALLEST address meeting two constraints simultaneously — (1) large enough to hold the requirement, and (2) aligned to a boundary evenly divisible by its own block size (a /25 block can only start at .0 or .128 within a /24, never at .64, because block boundaries must be powers-of-2-aligned for the resulting network/mask arithmetic to work correctly at all).

Why must a subnet's starting address be a multiple of its own size? Because the network address is DEFINED as "IP AND mask" — for THAT operation to correctly identify a clean block boundary, the block itself must start exactly where the mask's zero-bits (the host portion) are all simultaneously zero. A /25 block (128 addresses) can only correctly start at addresses where the low 7 bits are entirely 0 — which are exactly the multiples of 128 (.0 and .128 within a /24). This isn't a convention — it's a direct mathematical consequence of how AND and the mask define "network address" in the first place.

5. RFC 3021 (Exercise 2) and the /31 Special Case

The "reserve network and broadcast" convention exists because a block needs to be able to refer to "the whole block" (network address) and "everyone in the block" (broadcast) as concepts distinct from any single host. A 2-address block (/31) is too small for that distinction to be meaningful — with only 2 addresses total, there's no room left for actual hosts if 2 are reserved for group-addressing concepts. RFC 3021 (1996) formally recognized this for point-to-point links specifically (where "broadcast to everyone in this segment" is meaningless anyway — there are only ever exactly 2 devices on a point-to-point link) and redefined /31 to treat BOTH addresses as usable host addresses.
