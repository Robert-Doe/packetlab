Module 04 — Tutorial

Goal: stop treating subnetting as a memorized table lookup. By the end of this module you'll have built the calculator yourself, proven it correct against Python's own standard library, and drilled it into memory with an unlimited quiz generator.

Step 1 — run the calculator on a subnet you already know

Use the gateway/network from Module 01's dashboard (very likely something like 192.168.0.0/24):

cd module-04-ip-addressing-subnetting
python subnet_calc.py 192.168.0.0/24
node subnet_calc.js 192.168.0.0/24
Expected: both print identical output — network 192.168.0.0, broadcast 192.168.0.255, 254 usable hosts. This is almost certainly your actual home network's real capacity right now.

Step 2 — prove the math against the standard library

python subnet_calc.py --self-test
node subnet_calc.js --self-test 50
Expected: Python's self-test runs 500 random CIDRs through both this file's manual bit math AND Python's own ipaddress module, and reports a full match. Node's self-test shells out to the Python file directly and cross-checks against it instead (Node has no bundled IP-address standard library to use as an oracle) — also expect a full match.

Step 3 — the quiz, honestly, until you stop missing questions

python subnet_quiz.py 15
Don't peek at subnet_calc.py while quizzing. The entire value of this exercise is doing the binary math in your head or on scratch paper faster than you can open the source file. Run it daily for a week — subnetting speed is a skill that decays fast without repetition, which is exactly why this module gives you an infinite generator instead of a fixed worksheet.

Step 4 — VLSM: subnetting a real address space for a real design

python3 -c "
from subnet_calc import vlsm_allocate
reqs = [('Sales', 50), ('Engineering', 100), ('Guest WiFi', 20), ('Point-to-point link', 2)]
for a in vlsm_allocate('192.168.1.0/24', reqs):
    print(a['name'], '->', a['cidr'], f\"({a['usable_hosts']} usable)\")
"
Expected: Engineering (needs the most hosts) gets allocated first and gets the largest block (192.168.1.0/25, 126 usable), then Sales, then Guest WiFi, then the point-to-point link gets squeezed into a /30 at the end. Notice the blocks never overlap and each one starts on a boundary aligned to its own size — that alignment requirement is what Exercise 2 in Module 03 was setting you up to appreciate.

Exercises before Module 05

  1. Design your own home network's VLSM plan. Using your real /24 from Step 1, write a requirements list for how YOU would actually segment your house: main devices, IoT/guest, a small lab VLAN for later modules. Run it through vlsm_allocate and sanity-check the output makes sense.
  2. Implement the RFC 3021 optimization. The VLSM allocator currently gives every 2-host requirement a full /30 (4 addresses, 2 wasted). Modify vlsm_allocate/vlsmAllocate so a requirement of exactly 2 hosts uses a /31 instead (2 addresses, 0 wasted) — you already have the math in subnet_info's /31 special case from Module 04's calculator itself.
  3. Score yourself. Run subnet_quiz.py 20 three days in a row and track your score and time. This is the one exercise in the whole course that's pure repetition on purpose — subnetting fluency is a timed-exam and technical-interview skill, and it only comes from doing it enough times that you stop consciously computing it.
Before Module 05: you should be able to subnet a /24 into VLSM blocks on paper, by hand, faster than typing the command. Module 05 takes these subnets and asks the next question: once you have multiple separate networks, how does a packet find its way from one to another? That's routing — the mechanism a router uses to decide, for every packet, which interface gets it one hop closer to its destination.
